## 1. 技术决策总览（已锁定）

| 决策项 | 结论 |
|---|---|
| 客户端 | Android 原生，Kotlin + Jetpack Compose |
| 执行层 | **Shizuku**：首次经电脑 adb 授权一次，之后 App 免 root 获得 shell 级权限 |
| 目标机型 | OPPO Find X9，Android 17 |
| LLM 接入 | **统一 OpenAI 兼容协议**（/v1/chat/completions），多 Provider 可配置 |
| 模型能力 | 兼容 reasoning（思维链字段）+ Function Calling / 工具调用 |
| 命令协议 | 类 ADB 语法；Function Calling 优先，命令文本块回退 |
| 工具体系 | 工具注册表：内置默认集 + 用户自定义，JSON 导入导出 |
| 存储 | Room（SQLite）：会话 / 消息 / 记忆 / 工具 / 日志 |
| 记忆 | 本地长期记忆，关键词检索 + 注入 LLM 上下文 |
| 安全 | 三档执行策略（全部允许 / 需要允许 / 全部不允许） |
| 构建 | Gradle + AGP，targetSdk 对齐 Android 17 |

### 2.1 执行链路（一次完整 Agent 任务）
1. 用户输入（可带截图）→ 记忆检索 + 会话历史 + 启用工具清单 → 拼装上下文；
2. 调 LLM（流式）：思维链实时推送过程面板；
3. 模型返回工具调用（优先）或类 ADB 命令文本（回退）；
4. 解析 → 参数校验 → 高危判定 → 三档策略裁决（直接执行 / 确认 / 拒绝）；
5. Shizuku / 系统 API 执行，过程面板实时显示状态；
6. 结果回传 LLM → 多步循环（最多 N 轮，可配）→ 最终用户可读回答；
7. 日志记录（可开关）、记忆按需写入。

## 3. 执行层：Shizuku 集成方案（核心）

### 3.1 为什么用 Shizuku
Android 普通 App 沙箱无法执行 `screencap` / `input keyevent` / `pm uninstall` / `settings put` 等 shell 级命令。Shizuku 通过**一次 adb 授权**让 App 长期获得 shell 权限级能力，免 root、免常驻电脑。

### 3.2 首次激活流程（用户操作一次）
1. 手机安装 Shizuku 官方 App（或本 App 引导下载）；
2. 手机开启 **开发者选项 + USB 调试**；
3. 电脑执行 `adb pair`（无线配对）或 USB 连接后执行 `adb shell sh /sdcard/Android/data/moe.shizuku.privileged.api/files/start.sh`；
4. Shizuku 进入"已启动"状态，本 App 申请授权后即长期可用；
5. 后续使用不再需要电脑。

### 3.3 依赖与关键 API
- 依赖：`dev.rikka.shizuku:api` + `dev.rikka.shizuku:provider`
- 关键类/方法：
  - `Shizuku.ping()` / `Shizuku.bindRequestService()` / `Shizuku.checkPermission()` — 状态与授权
  - `Shizuku.newProcess(String[] cmd, ...)` — 执行 shell 命令（capture 输出/退出码）
  - `ShizukuBinderWrapper` — 包裹系统服务 Binder，调用系统级 API
  - UserService（可选）：自建服务进程内执行批量命令
- 降级策略：Shizuku 未启动时，可用工具自动降级到常规 API 可覆盖的子集，UI 提示"受限模式"。

### 3.4 命令映射总表（ADB 语法 → 执行方式）
| 类别 | ADB 命令 | 执行方式 | 风险 |
|---|---|---|---|
| 包管理 | `pm list packages` | Shizuku shell `pm list packages` | 低 |
| 包管理 | `pm uninstall <pkg>` | Shizuku shell `pm uninstall` | 高 |
| 应用 | `am start -n <pkg>/<act>` | Shizuku shell / 常规 Intent | 低 |
| 屏幕 | `screencap -p <path>` | Shizuku shell `screencap`（或 MediaProjection 兜底） | 低 |
| 输入 | `input keyevent <code>` | Shizuku shell `input keyevent` | 低 |
| 输入 | `input text <str>` | Shizuku shell `input text` | 低 |
| 文件 | `ls / cp / mv / rm` | Shizuku shell；私有目录内走常规文件 API | rm=高 |
| 设置 | `settings put system <k> <v>` | Shizuku shell `settings put` | 高 |
| 系统 | `dumpsys <svc>` / `logcat -d` | Shizuku shell | 低 |
| 剪贴板 | `clipboard set <text>` | 常规 ClipboardManager（低风险无需 shell） | 低 |

> 全部命令白名单化：只允许映射表中已注册命令，防模型构造任意 shell（如 `;` 拼接、`|` 管道注入）——详见第 5 章"命令白名单"。

## 4. LLM 网关设计（OpenAI 兼容协议）

### 4.1 协议层
- 统一 `POST {base_url}/v1/chat/completions`，SSE 流式；
- 配置项：`base_url` + `api_key` + `model` + `temperature/max_tokens`（可默认）；
- Provider 预设模板：豆包（火山方舟）、通义千问（DashScope 兼容）、DeepSeek、Ollama 远程、OpenAI 官方等，一键填充 base_url；
- 非 OpenAI 协议（Anthropic / Gemini）：预留适配器接口，本期不实现。

### 4.2 思维链（reasoning）解析
- 各模型在 OpenAI 兼容接口中的差异字段：
  - DeepSeek-R1 / Qwen3：响应含 `reasoning_content` 字段（流式逐段返回）；
  - 其他模型：无原生字段时，靠系统提示词引导模型输出 `[THINK]...[/THINK]` 计划块，或直接展示工具调用链作为"过程"；
- 统一抽象：`AgentThought { type: reasoning|plan|tool_call, content, ts }`，UI 过程面板统一渲染；
- 开关：设置页可关闭思维链展示（省 token / 少干扰）。

### 4.3 工具调用协议
- **优先**：OpenAI `tools` / `tool_calls` 规范 —— 系统把启用工具的定义（name/description/parameters JSON Schema）注入请求；
- **回退**：模型无工具调用能力时，用系统提示词要求输出命令文本块：
  ```json
  {"tool": "pm_uninstall", "args": {"pkg": "com.example.app"}}
  ```
- 工具定义注入与回退均可在设置页切换（自动检测 / 手动指定）。

### 4.4 上下文拼装
```
system: 角色说明 + 可用工具清单(启用项) + 命令输出规范 + 安全约束
memory: 检索命中的记忆片段（≤N 条，可配）
history: 当前会话最近 M 轮（可配）
user:   当前输入 (+ 截图 base64 走多模态字段)
```

## 5. 工具注册表与命令映射

### 5.1 工具定义 JSON Schema
```json
{
  "name": "pm_uninstall",
  "description": "卸载指定应用包",
  "parameters": {
    "type": "object",
    "properties": {
      "pkg": { "type": "string", "description": "应用包名，如 com.example.app" }
    },
    "required": ["pkg"]
  },
  "handler": "shell",            // shell | api | compose
  "command_template": "pm uninstall {pkg}",
  "risk": "high",                 // low | high
  "enabled": true
}
```
- `handler=shell`：走 Shizuku shell，用 `command_template` 白名单渲染参数；
- `handler=api`：绑定到 Kotlin 函数实现；
- `handler=compose`：组合多个既有工具（未来扩展）。
- **命令白名单**：解析时校验 `name` 必须命中注册表、参数严格按 schema 渲染进模板，**禁止**任何未注册命令与 shell 拼接字符（`; | & > < \` 等）进入执行层。

### 5.2 默认内置工具集（v1）
| name | 说明 | 风险 |
|---|---|---|
| pm_list_packages | 列出已装应用 | 低 |
| pm_uninstall | 卸载应用 | 高 |
| am_start | 启动应用/界面 | 低 |
| screencap | 截屏保存 | 低 |
| input_keyevent | 按键 | 低 |
| input_text | 输入文本 | 低 |
| file_list / file_copy / file_move / file_remove | 文件操作 | rm=高 |
| settings_put | 修改系统设置 | 高 |
| dumpsys | 系统服务信息 | 低 |
| logcat | 读取日志 | 低 |
| clipboard_set / clipboard_get | 剪贴板 | 低 |

### 5.3 安全三档
| 档位 | 行为 |
|---|---|
| 全部允许 | 所有工具调用直接执行 |
| 需要允许 | `risk=high` 弹窗确认，低危直接执行 |
| 全部不允许 | 每次执行前都弹窗确认 |

## 6. 思维链与过程可视化

- 过程面板数据流：`AgentThought` 事件流（reasoning 文本 / 计划 / 工具选中 / 命令渲染 / 执行状态 / 返回结果）；
- UI：可折叠卡片式时间线，逐步展示，支持展开/收起、复制；
- 持久化：消息表中单独存储 reasoning / tool_calls，可回看历史过程。

## 7. 长期记忆模块

- 存储：`memory` 表（本地 SQLite，不上传原始库）；
- 条目：`content` + `category` + `tags` + `weight` + 时间戳；
- 写入时机：对话中识别的事实（如"用户常用目录 /storage/emulated/0/Download"）、工具执行成功后提取的关键信息、用户显式"记住 xxx"；
- 检索：按当前输入做关键词（FTS）检索，取 Top-N 注入上下文；后续升级本地向量（sqlite-vec + 本地 embedding）；
- 管理界面：查看 / 编辑 / 删除 / 清空；设置页可关记忆注入。

## 8. 数据库设计（Room）

### 8.1 表结构
```sql
conversation(id TEXT PK, title TEXT, created_at INTEGER, updated_at INTEGER)

message(id TEXT PK, conversation_id TEXT, role TEXT, content TEXT,
        image_refs TEXT,           -- JSON 数组
        reasoning TEXT,            -- 思维链原文
        tool_calls TEXT,           -- JSON 数组（工具调用记录）
        command TEXT,              -- 实际执行的命令
        status TEXT,               -- ok | error | pending | refused
        result TEXT, created_at INTEGER)

memory(id TEXT PK, content TEXT, category TEXT, tags TEXT,
       weight INTEGER DEFAULT 1, created_at INTEGER, updated_at INTEGER)

tool(id TEXT PK, name TEXT UNIQUE, description TEXT, parameters TEXT,  -- JSON Schema
     handler TEXT, command_template TEXT, risk TEXT, enabled INTEGER,
     builtin INTEGER DEFAULT 0)

log(id TEXT PK, conversation_id TEXT, user_query TEXT, command TEXT,
    status TEXT, result TEXT, created_at INTEGER)
```
- 索引：message(conversation_id, created_at)；memory(tags / FTS)；log(created_at)。

## 10. Android 17 / OPPO Find X9 适配注意点

1. **targetSdk 与 compileSdk**：对齐 Android 17；ColorOS 对后台/自启动有额外管控，本 App 前台运行即可，不做后台保活对抗；
2. **MediaProjection**：Android 14+ 每次截屏需用户确认；Shizuku shell `screencap` 可绕过该限制，是首选；
3. **无障碍（未来扩展）**：ColorOS 需手动开启无障碍服务开关，不在首期范围；
4. **Shizuku 兼容性**：Android 17 上 Shizuku 需保持最新版本；激活后建议本 App 启动时自检 `Shizuku.ping()`；
5. **OPPO 应用市场限制**：自用安装 APK 需允许"未知来源"，正式安装时提示用户。
